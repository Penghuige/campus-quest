# CampusQuest 首次容量报告（2026-10）

Spec: `docs/superpowers/specs/2026-10-29-load-testing-design.md` ·
方法: 容量估算 → 场景即代码 → 正确性断言（见 ADR 0001）

## 一句话结论

单机形态下，系统在 **50 并发提交者**目标负载上零错误零丢失通过全部正确性断言；
**300 人抢 60 名额零超发**；真实崩溃点在 **~200 并发提交者**（本机磁盘先于应用倒下），
并挖出一个生产级并发缺陷：**上传意向流的数据库死锁**（已移交修复 PR）。

## 目标与估算（面试讲稿的起点）

学校 ~3 万人 → 一门 1000 人报名的大课作业 → 拖延定律让最后 10 分钟挤进 ~100 人 →
现实在途并发 ~10–20，**目标按 50 并发打**（留余量），崩溃点由递增腿实测。

## 环境与 SUT 形态（诚实声明）

- 单机：uvicorn `--workers 2` + 1 Celery worker + beat；PostgreSQL 16 / Redis 7 /
  MinIO（`infra/docker-compose.yml` + loadtest overlay，慢查询日志 200ms）
- 单 locust 进程（同机）；API 级压测（不经浏览器渲染）
- **登录容量未测**（设计决定）：每 IP 每小时 50 次的登录限流使单源压测不可能，
  套件用种子期离线铸 token（与登录同一签发代码路径）
- 本机磁盘 98% 满（社会性发现：MinIO 桶堆着历史压测上传，retention=180 天不清）

## 结果矩阵

| 场景 | 负载 | 结果 | P99 | 正确性检查 |
|---|---|---|---|---|
| S1 截止抢交（目标） | 50 并发 / 4.5 min | 50 提交全成功，0 错误 0 限流 | 862 ms | ✅ check_s1 全绿（零丢失/零重复/§9.3 分档/排水 7.7s） |
| S1 递增 | 100 并发 | 162 提交，1 次 500（**死锁**，0.09%） | 2.7 s | 发现死锁（见下） |
| S1 递增（崩溃点） | 200 并发 | 507 磁盘满级联（52s 内打爆 MinIO 卷）→ 404 连锁，err 6.3% | 7.9 s（complete 腿 11s） | 环境限制先行，应用 P99 在 100 并发已开始劣化 |
| S2 开抢名额 | 300 人 / 60 槽 | **恰好 60 胜，零超发**，240 干净 4xx 拒绝，0 次 5xx | 1.15 s | ✅ check_s2 全绿（无超发/无人重复/占用一致） |
| S3 读基线 | 20 并发 | 464 读全成功 | 27.5 ms | 对照组 |

业务性 4xx（在途冲突、截止后拒绝）全程单独计数，不计入错误——这是产品在正确地说"不"。

## 发现（按重要度）

1. **上传意向流死锁（生产级，移交修复）**：100+ 并发下 `POST /submissions/upload-intent`
   偶发 PostgreSQL `DeadlockDetectedError` → 500（~0.1%）。锁图：intent 流的
   `SELECT ... FOR UPDATE`（claim 行）与验证 worker 的裸
   `UPDATE assignment_claims SET status='UNDER_REVIEW'` 相互等待——worker 绕过了
   upload_service 文档规定的 user→claim→intent 锁序。慢查询日志佐证：竞争窗口内
   claim 行 UPDATE 996ms、FOR UPDATE 290ms。**该修复属产品正确性变更，需专属 TDD PR**
   （确定性并发复现 + 锁序对齐），不在本容量 PR 内夹带。
2. **磁盘是单机形态的第一道天花板**：200 并发时 MinIO 卷 52 秒被 ~30MB 级上传打爆
   （叠加历史残留 3.2GB）。容量规划里"对象存储增长率"必须与 QPS 一起算；
   压测桶应定期清理。
3. **写路径 P99 随并发的劣化曲线**（862ms@50 → 2.7s@100 → 7.9s@200）：
   主导因素是 claim 行锁竞争（慢查询日志）+ 大文件 PUT 的带宽分享。可观测性（B 方向）
   落地后应给出按端点的分解。

## 修复轮

本轮交付以"记录+移交"收口：死锁修复需要产品级回归测试（已在报告中立项），
其余失败均为环境限制（磁盘）而非代码缺陷——符合计划的
"comfortably above target + 实测崩溃点"合法结局。
