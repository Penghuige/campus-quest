## 备注（覆盖形态与边界，非缺口）

- **三层防线**（FR4/FR5）：候选查询排除（by construction）→ 服务级 per-record guard（stale listing 防线）→ claim 时全 guard 重评（TOCTOU 关闭，真 PG 独立连接，G15 形态）。§27「不得误删」的并发安全最终落在第三层；三层各有独立测试面。
- **claim/lease/token 机制**（FR12）为 pass 4b/5a/final A 的实现深化，非 spec §13/§27 明文要求；owner 裁决（Option B、claim-ownership、 fencing）记录在 `tests/workers/test_cleanup_deletion_claim.py` 与 `app/modules/files/cleanup_service.py` 的 docstring。本矩阵按其守护的 spec 不变量（幂等 + 不得误删）收录证据，不把机制本身当作 spec 要求登记。
- **孤儿上传意图清理**（`test_orphan_intent_cleanup_matrix` 等意图侧测试）：同一清理任务的第二阶段，spec §13/§27 未单列其语义（§10 意图过期属 submissions 邻域）；其幂等/404/围栏证据已被 FR9/FR11/FR12 行内引用，不单独建 spec 行。
- **边界互引**：submissions-validation 矩阵 S4/G-4 是「原文件名」的长度限制与清理（§10 上传安全域），与本域文件保留策略无行重叠；claims-lifecycle 矩阵 C31 是 Claim 超时 Worker（`test_expire_claims`）的幂等形态，本域 FR9 仅收清理 worker 自己的证据；两邻域矩阵均无 §13/§27 行，无让渡。
- **e2e 证据**（FR7/FR9/FR11 引用的 `test_duplicate_cleanup_job_reconciles_without_metadata_loss`）跑在真实 PG+MinIO 栈、走生产 S3 适配器与真任务入口，是本域唯一的真适配器级端到端证据。
