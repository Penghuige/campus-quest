## 待修问题与建议验收标准

### F01 — P1：站内离开丢失未保存输入

复现：本人项目→招募管理→新建→填写岗位名 `模拟未保存测试岗位`→点手机底部“创新创业”→浏览器返回→重新打开新建。没有确认弹窗，岗位名为空。用户正常切换页面即可损失长表单输入，应优先于视觉优化。

源码依据：`frontend/src/features/innovation/RecruitmentEditor.tsx:35` 只注册 beforeunload，`:42` 只保护本地返回按钮。站内 Link 切换不触发 beforeunload。ProjectDraftsView/AchievementDraftsView 有相似保护方式，但本轮未实际复现这些表单，不能扩大已证实范围。

建议验收：顶部、底部、侧栏、返回我的项目和浏览器返回等离开路径都有一致保护或可恢复草稿；取消离开保留所有输入，确认离开符合文案。恢复机制不得未经授权公开内容或联系值。当前表单未保存提醒只解释发布前要保存，不能替代离开保护。

证据：`lost-unsaved-input.jpg` 是返回后空表单截图，交互过程还结合实际观察到的“没有弹窗”与输入值，不能单靠该截图证明丢失。

### F02 — P2：权限/不存在被解释成临时服务故障

观察者访问他人招募管理以及运营访问新模拟项目管理，均返回 404，不泄露私有内容。但“服务暂时不可用，请稍后重试”会让用户反复重试、误判平台出故障。观察者实际重试一次仍得到同样提示。

源码依据：`RecruitmentWorkspace.tsx:26` 无条件使用 SectionError；`frontend/src/lib/errors.ts:73` 将 NOT_FOUND 纳入系统错误，`:223` 的 describeSectionError 映射成服务不可用。

建议验收：该管理入口对 404 使用“不存在或不可访问”的中性解释及返回本人项目动作，不区分他人的真实资源是否存在；临时网络/5xx 保留重试。不要直接修改共享错误映射而忽略其他页面的含义。

证据：`observer-forbidden.jpg`、`permission-retry-does-not-help.jpg`、`operations-forbidden.jpg`；真实 404 另在本轮 API 日志确认。

### F03 — P2：其他阶段仍展示创意起步专属空字段

“其他阶段”下目标/初步方案非必填，实际空着可以发布，公开详情正确省略它们。但是编辑器仍占用长段空间，确认弹窗又写“阶段目标：未填写／初步方案：未填写”，用户容易认为漏填，犹豫是否能发布。

源码依据：`RecruitmentEditor.tsx:118` 无条件渲染字段列表，`:138` 的确认预览同样无条件枚举它们。

建议验收：条件字段及预览与阶段要求一致；不适用的字段隐藏或明确说明，不显示像错误的“未填写”。来回切换仍保留临时输入，不新增重复阶段字段，不改业务必填规则。

证据：`mobile-new-form.jpg`、`mobile-publication-preview.jpg`。后者为本轮真实 V1 发布确认画面。

### F04 — P2：联系格式错误不足以指导纠正

QQ 填 `abc` 后，输入框及联系授权区同时显示“请填写有效的授权联系值；每类渠道只选一个”。聚焦、错误关联有效，但用户不知道长度、首位或允许字符；手机输入也没有按邮箱/手机号设置输入类型。

源码依据：`recruitmentForm.ts:112` 为所有非法渠道提供同一错误；`RecruitmentEditor.tsx:124` 全部渠道 type=text、没有格式提示，`:125` 再展示总错误。

建议验收：每类渠道给匹配实际验证器的格式说明/错误与安全模拟示例；邮箱/手机有恰当语义和移动键盘；仍逐渠道显式授权，不自动使用账号绑定值。保留有效焦点关联，避免两条相同错误争夺注意。

证据：`invalid-qq.jpg`、`mobile-missing-contact.jpg`。

### F05 — P2：编辑入口与联系读取成功的无障碍反馈不足

键盘 Enter 打开编辑器后，焦点实际为 BODY；编辑标题没有聚焦或说明。联系读取成功仅追加 dl，主内容没有 status/aria-live，也未移交结果焦点。能看到页面不代表使用读屏的学生知道发生了什么。

源码依据：`RecruitmentEditor.tsx:112` 标题无焦点管理；`RecruitmentContacts.tsx:25` 成功结果只有 dl。编辑器保存/发布结果的 status 和发布弹窗焦点行为本轮已验证有效，不需要全部重写。

建议验收：进入新建/编辑时把焦点放到合适标题或首控件，退出返回合理位置；联系读取成功有结果存在的公告或适当焦点，不自动播报整段联系值。增加真实读屏验收。本轮仅完成键盘与 DOM 语义检查，没有实际读屏结果。

### F06 — P2：零基础选项公开表达不准确

“零基础友好：否”公开转换成“有能力要求”。零基础友好的岗位同样可以有能力要求，这个标签没有准确传达是否接受新手。

源码依据：`PublicRecruitmentsView.tsx:26` 列表、`:33` 详情的二分标签。

建议验收：使用直接对应表单选项的公开标签，保持列表、筛选和详情一致。具体措辞可以优化，但不能把该标记换成另一业务概念。

证据：`mobile-revoked-one-channel.jpg`。模拟内容“无需经验”是本次只切换布尔项的测试资料，不据此认定系统自动造成正文矛盾。

### F07 — P3：关闭后仍展示“下次提醒”

最后渠道撤销关闭及主动关闭后均显示“当前已关闭 · 下次提醒 2026年11月11日…”，使人误以为已经关闭还会继续被提醒。本轮没有等待该日期，不据此断言 worker 仍发提醒。

源码依据：`RecruitmentEditor.tsx:114` 只判断 next_remind_at，不判断当前状态。建议仅对符合提醒条件的岗位展示“下次提醒”，历史时间如需保留应使用准确含义。

证据：`last-contact-closed.jpg`、`final-closed-receipt.jpg`。

### 可排在上述问题之后的界面整理

- 手机搜索筛选区占据首屏大半，长表单约三屏；可收纳次要筛选、缩减非适用字段、改善内容与操作层级。桌面阅读宽度也可更克制。本轮检查页面没有发现水平溢出，但未覆盖全部断点。
- 保存草稿与发布是不同目标，操作视觉层级还可更清晰；不把它们合成自动公开的动作。
- 旧详情提示刷新岗位但没有就地刷新按钮，用户要自行寻找浏览器刷新。
- 既有项目的审核成果名称与招募独立介绍名称不同，跳转时缺少版本来源解释；规则允许独立介绍，建议解释来源，不修改成果复审与招募免审边界。
- 招募详情返回列表可能丢失之前的筛选上下文，可在后续改善，不影响本轮正常搜索与清空的通过结论。
- 首页既有演示成果正文仍提“免复审更新”，与当前已确认的成果更新复审规则冲突；状态另显示“更新复审通过”。这是存量模拟资料的文案问题，本轮未编辑该记录，后续应在保留数据前提下更新演示说明。
