# 双创身份基础：负责人资料与运营授权

依据工作区《华师令创新创业板块独立需求说明书》v0.7 §4、§8及技术实现文档 V1.1，结合当前人类确认：三库功能 demo、可使用预置演示账号、每天投入1–1.5小时、先保证可操作与正确性。当前基础为0025私有项目草稿；不重写原校园任务功能。本计划不把三库 demo 缩减为静态页面。

## 本次实现的可验收切片：本人负责人资料

正常学生填写并保存姓名、学号、专业、年级四项资料，刷新读取、修改保存。仅保存四项，不增加附件、经历证明、联系方式或审批理由。输入为本人填写资料，不作为身份核验结果；不要求学号必须与现有账号名相同，不改变登录身份。

资格开通方式仍属原文待确认事项。保存资料不自动取得负责人资格，也不创建虚构的审核队列或“审核通过”状态。将来正式发布接口必须另行检查真实资格；当前草稿准备权限不变。预置 demo 资格须通过明确的本地种子实现，不能由填表触发。本切片不开放资格或发布接口。

原任务规约禁止学生页面展示学号等隐私；这里按用户提供的新需求作窄范围扩展：四项仅在本人私有表单和本人 API 返回，绝不加入公共列表、共享用户 DTO 或日志。管理员/教师不因全局角色而取得此读取接口。

### 数据与 API

- 新增迁移0026及表 `ie_owner_profiles`：user_id主键/用户外键，name最多80、student_no最多40、major最多120、grade最多40字符，均trim后非空；version正整数，created_at/updated_at为UTC。长度限制是实施约束，不宣称来源于学校制度；学号作为字符串保留前导零，不臆造数字格式。
- `GET /api/v1/ie/me/owner-profile` 返回 `{profile: null}` 或明确的四项资料+version+时间 DTO；无user_id、资格状态。`PUT` 完整四项加预期version；首次version=0，已有记录需匹配正version，否则409 `OWNER_PROFILE_VERSION_CONFLICT`。额外字段全部拒绝。
- 使用现有Bearer与ACTIVE/STUDENT依赖，服务在当前事务内重新读取并锁定用户状态，与停用串行。跨域只用users的id/role/status Core验证锁接缝，不导入identity ORM。每人一行由PG主键保证；同初始版本/同修改版本并发仅一个成功。
- 事务由服务控制；敏感读取、写入均通过AuditLogWriter持久化审计，actor/target/reason/request上下文可追溯。审计只记录动作和版本，不记录四项资料。审计失败不得返回成功或泄露敏感响应。私有响应 `Cache-Control: private, no-store`。
- 无目标用户参数或他人资料路由。重新发送不重复建行，旧版本不会覆盖新内容；网络结果不明时读取最新版本确认，前端保留当前输入，不谎报未写入或已保存。

### 页面

个人中心及草稿准备页提供“负责人资料”入口，复用现有页面布局、AuthField、SubmitButton、状态组件，不新增依赖或设计系统。四项必填，逐项错误与焦点、加载/空表单/失败重试/保存反馈；账号变化销毁私有表单，旧请求结果不得进入新会话。没有发布/审批空按钮。

冲突及未知保存结果保留输入，允许读取最新资料作比较，只有用户明确载入才替换。桌面和手机无横向溢出，键盘可完成。未保存修改在刷新/关闭浏览器时有提醒；普通站内链接不承诺路由拦截。

### 测试与交付

先写矩阵预期和失败用例，再实现。DTO验证四项必填/trim/Unicode长度/额外资格字段拒绝；真实PG/API验证跨刷新保存、无资料响应、Bearer与Cookie边界、停用/非学生拒绝、A/B隔离、审计不含PII、审计失败不提交。独立连接验证首次和更新同版本竞争、提交后独立读取。数据库直接写入验证约束。

## 紧接着的切片：管理员指定运营人员（后续同日已实现）

运营身份属于双创域授权，保持原全局STUDENT，不升级为TEACHER/ADMIN。管理员按现有2FA及管理网段规则授予/撤回，操作真实持久化并审计；运行期检查新鲜账号状态和授权。学生不能自授权，撤权后下一次业务请求拒绝。后续成果审核还需排除本人参与项目，运营不获原Task发布和调积分权限。

实施前补充该切片的API、状态转移、并发与撤权验收契约；不先创建返回成功的空授权接口。用户约定默认Sol High，需要切换时先明确提醒，不假定已自动切换。常规编码可用Sol Medium；权限设计及最终审查使用Sol High。
