# V1.1 Wave 1 — Staff Login Convenience Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Teachers log in with email + 6-digit email code (two steps, zero TOTP); admins add email-code login with mandatory TOTP and a 30-day remember-device option; invitation acceptance drops mandatory TOTP for teachers; all accounts get a 5-failure/15-min lockout; first login nudges auto-generated nicknames to be renamed.

**Architecture:** Mirror the existing SMS-OTP challenge pattern (challenge row → hashed code → rate-limited issue/verify) onto the SMTP sender port from PR #79; add a `RememberedDevice` table keyed by hashed random cookie; add a Redis-backed per-account failure guard shared by student/staff login paths. Old password+TOTP channel stays untouched.

**Tech Stack:** FastAPI + SQLAlchemy 2 async + Alembic + Redis (redis-py) + existing `EmailSender` port; Next.js 16 client islands + Playwright e2e.

**Spec:** `docs/superpowers/specs/2026-10-15-v1.1-experience-and-administration-design.md` §2, §6.

## Global Constraints

- Email code: 6 digits, valid 5 minutes, max 5 verify attempts per code, 60s resend cooldown per email (`emailcode:cooldown:{email}` Redis key, TTL 60).
- Lockout: 5 consecutive failures per account → 15 min cooldown (`login:fail:{user_id}` Redis, TTL 900); success resets; error envelope `ACCOUNT_LOCKED` with `retry_after_seconds`.
- Remember-device cookie: `urlsafe(32)` value, SHA-256 hash stored, 30-day expiry, HttpOnly + Secure + SameSite=Lax, name `cq_staff_device`.
- Anti-enumeration: `POST .../email-code/request` always returns 202 with an empty body regardless of whether the email exists / is staff / is active.
- TEACHER accept-invitation: optional password, straight to ACTIVE, no TOTP. ADMIN accept: unchanged (mandatory TOTP + recovery codes).
- No new Python dependencies. All new admin-visible behavior writes audit rows via the flush-only `AuditLogWriter` pattern (PR #80).
- OpenAPI snapshot + generated TS types regenerate in the same PR as endpoint changes (AGENTS docstring rule).
- Every commit message plain conventional style, no AI trailer.

## Review Focus

1. **Email-code request as an oracle:** an attacker probes `/email-code/request` for arbitrary emails — endpoint must be constant 202, constant timing shape (no user-lookup error divergence), and must never reveal staff existence. Test pins: integration test asserting identical status/body/timing-band for unknown/student/locked-staff emails (Task 5).
2. **Code brute force:** 6-digit code must not be guessable by hammering verify — 5 wrong attempts kill the challenge; a 6th attempt with the CORRECT code must still fail. Test pins: unit test in Task 6.
3. Remembered-device cookie theft replay: a stolen cookie must not survive admin session revoke (T3 revoke clears devices; Task 6 asserts cookie invalid after revoke_all).
4. Lockout counting must not lock on rate-limited requests (429 ≠ failure) and must count the email-code path, the password path, and the student path uniformly. Test pins: Task 7 parametrized test.
5. TEACHER invitation acceptance without password must yield a usable email-code-only account (login works with no password ever set). Test pins: Task 8.
