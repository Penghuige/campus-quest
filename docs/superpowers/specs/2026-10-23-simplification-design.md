# 简化批设计（默认简单、严格可选）

- **状态**：Approved — owner 2026-10-23（"把加强作为可选项"；先做 P1+P2，平台加"通用"项）
- **范围**：提交校验 schema 可选化（P1）+ 任务创建一键化（P2）
- **关联**：`2026-09-19-campusquest-design.md` §6.2 发布校验、§10.1 两族文件、§12 校验 DSL；本文件是对上述条款的修订

## 1. 总原则

普通老师/学生的主路径只问**业务上必需**的信息；校验强度、导入细节、通知通道等全部收进「高级（可选）」。默认行为是宽松可用的，严格校验是显式开启的能力。

## 2. P1：提交校验 schema 可选化

### 2.1 任务配置

- `submission_schema` 与 `submission_schema_version` 在创建/编辑/发布时**均为可选**。
- **不配置 schema（默认）**：结构化任务进入**宽松校验**——文件可解析（按格式族）、有表头、至少一行数据，即通过机器校验，进入教师人工审核。不做列名/类型/唯一性检查。
- **配置 schema（显式开启）**：保持现有严格校验（§12 DSL，列/类型/唯一性/行数）。
- 前端：高级折叠区默认留空；提供「使用模板」按钮填充示例（仅作起点，不强制）。文档型任务约束不变（schema 必须为空）。

### 2.2 发布门禁修订

- 结构化任务发布**不再要求** schema/version。
- **草稿首次发布要求至少 1 个任务单元**（修复"忘记设置完成人数"）：DRAFT→PUBLISHED 时若任务单元数=0，返回稳定错误码并提示「请先设置完成人数（任务单元）再发布」。PAUSED→PUBLISHED 不受此限。

### 2.3 校验结果 UX

- 宽松模式失败（无法解析/无表头/无数据行）沿用失败报告，但首行文案给出下一步动作（如「请确认文件有表头并至少一行数据」）。
- 严格模式缺列时提示「缺少列 <name>，可下载本任务模板」。

## 3. P2：任务创建一键化

### 3.1 主表单（默认可见）

只包含：任务名、说明、**需要多少人完成（target_count，1–200，必填）**、截止时间（天数或固定日期二选一，默认 7 天）。

其余字段使用默认值：奖励分 10、稀有度 NORMAL、文件类型 CSV、大小上限 10 MB、领取截止窗口 60 分钟、通知关闭。

### 3.2 自动生成任务单元

- 创建请求新增可选 `target_count`。提供时，后端在**同一事务**内创建 `target_count` 个任务单元：
  - 平台 = **通用**（新注册表项，见 3.3）
  - 关键词 = `单元1`…`单元N`（可在高级中通过现有导入/编辑调整）
- 未提供 `target_count` 时行为不变（草稿，任务单元仍走导入）。
- 高级折叠保留：奖励/稀有度/文件类型/大小/schema（可选）/领取窗口/通知通道/自定义单元导入（platform,keyword CSV）。
- 200 上限与导入行数上限一致；超出返回校验错误。

### 3.3 平台注册表新增「通用」

- 新迁移种入平台行：`code = generic`，显示名「通用」，排序置末。
- 学生端/管理台显示名照常走注册表；既有任务与平台行不受影响。

### 3.4 学生侧

主路径不变；「我的任务」与任务详情按既有契约。宽松校验失败不改变 claim 状态（保持可重试）。

## 4. 契约与交付

- OpenAPI/TS 快照同 PR 再生；新增错误码走 interfaces.md 注册表。
- 矩阵：任务创建（target_count 自动单元/上限/通用平台）、发布门禁（零单元拒绝/暂停恢复不拦）、宽松校验（通过/解析失败文案）、严格校验回归。
- 迁移：0033 平台通用行（幂等 ON CONFLICT）。
- 交付序：后端 PR（schema 可选+发布门禁+target_count+迁移+契约）→ 前端 PR（主表单简化/高级折叠/校验文案）→ 一次部署。
