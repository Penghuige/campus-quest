# R4 人才库设计规格

日期：2026-10-12。分支：`codex/innovation-platform`。

状态：用户已确认聊天中的 R4 设计方向，并明确选择本轮同时支持作品/证明文件上传。书面规格交付后，用户授权“你站在用户视角感觉合理的话就推进吧”；代理从无经验建档、明确授权、文件替换与关闭隐私角度重新核对并认可。已形成 [详细实施计划](../plans/2026-10-12-innovation-talent-plan.md)，按此前本会话原生方式连续推进；功能完成状态以计划和交付回执为准。

## 1. 交付与需求依据

本轮提供一个真实可用的闭环：学生维护本人档案和可选作品 → 私有预览 → 主动开启 → 其他校内用户搜索、查看优势、按授权联系或下载作品 → 本人关闭后旧直链也不能继续读取。

| 依据 | 本轮解释与交付 |
| --- | --- |
| 工作区《华师令创新创业板块独立需求说明书.docx》v0.7，TA-03、TA-05 | 技能标签与个人优势；新生无项目/比赛经历也能建档；经历、作品链接与证明文件选填；标准标签加补充说明和新增标签建议 |
| TA-04 | 三种合作状态；选定外部联系方式；没有站内邀请、私聊或投递 |
| TA-06、AC-01 | 默认不公开，本人主动开启；校内身份校验；不公开学号；关闭同时限制列表、搜索、直链、联系和文件 |
| 用户本轮新增选择 | 本轮同时支持作品/证明文件上传；不是只做文字和链接 |
| 已确认 R4 聊天设计 | 独立人才档案；保存与公开分开；公开更新由本人确认；公开开关和合作状态分开；上传并不代表能力核实 |
| 已确认总规划 | 预置演示账号与明确标注模拟资料；学校 SSO 最后；不重置开发数据、不改 main、PR 保持 Draft、不自动合并 |

具体长度、分页、文件库存与锁策略是本规格的工程选择，不冒充需求原文已规定的数值。技术参考中的历史成果免复审方案不适用于当前成果规则。

不纳入 R4：导师库、共同管理/转让、完整运营治理、推荐与培训、积分/徽章奖励、学校认证、任务历史自动关联。TA-02/TA-07 的激励归 R8；标签建议的收集在本轮，运营审核、合并标签的工作台归 R7。本轮不展示虚假的“已核实”“已推荐”或奖励成功。

## 2. 用户入口和操作

- 校内浏览：`/innovation/talents`，人才详情 `/innovation/talents/[id]`；创新创业首页开放人才库入口，导师库仍如实标记未开放。
- 本人维护：`/profile/talent-profile`，从“我的”进入；仅 ACTIVE STUDENT 维护自己的档案，不要求负责人资格或项目权限。
- 本轮不新增运营人才编辑入口。现有身份、运营导航与招募权限保持各自边界。

本人页面分为基本资料、技能优势、合作意向、可选经历/作品、联系授权。页面持续说明当前是“未公开”还是“公开中”，公开中是否另有未发布修改；按钮明确为“保存草稿”“预览并开启展示”或“预览并更新展示”“关闭展示”。保存不会发布。

预览是本人私有预览，列出将展示的姓名/院系/年级、作品文件和联系渠道，明确提示资料为自述、文件检查不是平台能力认证。确认动作只针对已保存的完整版本；表单有未保存修改时先引导保存，不能悄悄发布旧内容。开启/更新的同意不预勾选。

正在公开的档案保存修改后，旧公开内容继续展示，直到本人明确更新。无须成果式运营审核。关闭后本人仍能查看和修改草稿；再次开启需要重新预览和确认，不自动恢复公开。

合作状态“暂不接洽”仍可展示档案，明确显示状态；它不自动关闭公开开关，也不自动撤回已授权渠道。状态变化与其他公开字段一样，通过明确更新进入公开版本。

## 3. 字段与最小可发布条件

字符串去除首尾空白；空白视为空；以下长度单位为 Unicode 字符数，前后端一致。私有草稿允许基本信息不完整，但格式/最大长度始终校验。

| 字段 | 约束 | 开启/更新展示时 |
| --- | --- | --- |
| 姓名、院系、年级 | 上限分别 50、100、30 | 三项必填；由本人明确填写，不从负责人私密资料静默导入 |
| 个人介绍、个人优势 | 上限分别 1000、2000 | 两项必填；允许描述文书、美工、PPT、路演等优势，不要求经历 |
| 标准技能标签 | 0–10 个去重、有效标签 ID | 至少 1 个；补充文字不能冒充标准标签 |
| 技能补充说明 | 上限 1000 | 选填，可随公开内容检索 |
| 合作方向、希望承担角色 | 上限各 500 | 选填 |
| 每周可投入时间 | 整数 0–168 小时或空 | 选填，空表示未填写；0 表示当前无可投入时间 |
| 协作方式 | 线上 / 线下 / 均可 / 未填写 | 默认未填写，不替用户推断 |
| 合作状态 | 寻找项目 / 愿意了解机会 / 暂不接洽 | 必须明确选择；新建草稿可未选择 |
| 经历说明 | 上限 3000 | 选填，不要求比赛或项目经历 |
| 作品链接 | 最多 5 条；标题 1–100、URL 最长 2048 | 选填，只接受绝对 http/https URL；不自动抓取/验证外站；安全外链打开 |
| 公开作品/证明文件 | 最多 5 个 | 选填，每个 READY 且本人明确选中；文件安全检查不等于业务真实性核实 |
| 联系授权 | 微信、QQ、邮箱、手机各最多 1 个 | 全部选填；无授权时正常发布，详情显示“暂未提供联系方式” |

姓名不从昵称推断为实名；本轮不宣称学校实名核验完成。公开字段不包含学号、账户绑定联系资料、负责人资格材料或原任务记录。演示档案与文件标题/内容明确标注“模拟”。

联系输入复用现有微信/QQ/邮箱/手机格式契约，展示具体格式与就地错误；未经本人填写及选择的账户绑定值不读入。普通详情只提供授权渠道种类；点“查看联系方式”后才请求并显示联系值，成功公告不朗读具体值。不在 DOM、预加载数据或持久缓存藏入联系值。

标准词表首版包含文书撰写、美工设计、PPT 制作、路演答辩、产品设计、前端开发、后端开发、数据分析、运营推广、项目协调，以可重复、确定的初始数据建立；不覆盖已有词表。标签建议为 1–50 字，理由选填最多 500 字，学生提交后如实显示“已收集，等待运营整理”，不立刻进入标准词表或承诺处理日期。同一人相同规范化名称的未处理建议去重；本轮没有运营处理按钮。

## 4. 保存、公开和版本

`TalentProfile` 每个用户最多一条，数据库唯一约束维护该不变量。独立持有私有编辑数据、聚合版本 `version`、公开版本指针、展示开关 HIDDEN/VISIBLE、治理状态 NORMAL/TAKEN_DOWN。治理状态供后续 R7 使用；本轮没有治理工作台，开启/保存不能清除治理限制。

`TalentRevision` 是不可变的公开快照，含展示字段、选定联系值与文件引用；保存草稿不创建公开快照。开启/更新在一个事务内验证完整数据、身份、版本与文件，写快照并移动指针。联系值仅在受限数据层及主动读取响应中出现。

首次本人读取返回明确的“未建档”空状态，而不是服务故障；首次创建以 version=0 表示尚无档案，之后使用服务端返回的 version。标准标签名称随公开快照保存，后续词表变动不能悄悄改写历史快照。

| 动作 | 私有草稿 | 对其他人的影响 |
| --- | --- | --- |
| 新建/保存 | 创建或更新，增加 version | 默认隐藏；已经公开则保留旧快照 |
| 开启/更新 | 必须基于已保存 version，明确同意 | 新不可变快照原子替换；VISIBLE |
| 关闭展示 | 保留私有数据、增加 version | HIDDEN，立即拒绝后续公开读取，不删除历史 |
| 撤回公开渠道 | 同时取消该渠道草稿授权，增加 version | 建立去掉该渠道的新公开快照；其他字段继续展示 |
| 撤回公开文件 | 文件永久撤回、从草稿选择移除，增加 version | 新快照去掉文件，旧文件地址也不能读取；其他字段继续展示 |

公开资源具有单调递增 `public_version`：开启、更新、关闭和公开撤回都递增。文件/联系的主动读取带详情页看到的 `expected_public_version`；仍公开但版本改变返回 409 并要求刷新，关闭/不可见优先返回中性 404。不能把旧页面的授权点击应用到新版本。

公开联系撤回后，日后本人可以重新填写、选择并明确发布；文件撤回不可逆，重新展示必须重新上传检查。从草稿取消文件勾选只是未发布修改，不立即影响旧快照；界面同时提供动作明确的“撤回公开文件”，避免把编辑与撤权混淆。

新建、保存、开启/更新、关闭、撤回的命令带 `request_id` 与预期 version；命令日志记录请求指纹和安全的回执，不记录联系明文或文件内容。相同 key 和相同请求只执行一次；相同 key 不同载荷冲突。重放历史成功回执不恢复已经关闭的展示或被撤回权限，客户端随后读取当前状态。

不同命令对同一旧 version 并发时只允许一方成功，另一方稳定 409；页面保留本人新输入并显示当前状态，不擅自覆盖。失去回执是“结果待确认”，用原 key/原载荷查明；不自动换 key 再发。文件检查只推进文件自己的版本，发布事务仍重新检查文件当前状态。

## 5. 文件上传、检查、撤权

每个文件允许 PDF、PNG、JPEG，实际字节上限 **10 MiB（10 × 1024 × 1024）**，非空；名称最长 200 字，去除控制字符和路径信息，只作为展示元数据。每份档案最多 **10 个未移除、未撤回的上传记录**（包括待上传/检查/失败记录），给 5 个公开文件整批替换留下空间；每个公开快照最多选择 5 个。这是首版库存限制，不代表历史材料保留政策。

`TalentFile` 独立归属于人才档案，包含元数据、存储 key、创建幂等信息、状态、校验摘要、检查尝试 token/租约、移除/撤回标记与版本。**不能借用成果附件记录或成果的负责人权限。** 复用 ObjectStorage 和 EvidenceScanner 的底层接口；给存储端口、真实 S3/MinIO adapter、组合根和测试 fake 增加真实人才文件命名空间，不能拿人才 UUID 冒充 achievement_id。

流程：申请私有上传凭据 → 精确上传原始字节 → 完成检查 → READY → 勾选公开 → 预览确认。上传凭据有效期 15 分钟，服务器生成 key、绑定 MIME/长度、使用 write-once 的 `If-None-Match: *`。此期限限制上传凭据，不阻止对已经上传的对象稍后完成检查。上传凭据只给本人，不是阅读授权；旧凭据即使尚有效也不能让移除/撤回记录重新进入 READY 或公开。再次申请不得绕过库存锁或重用旧 key。

检查状态 PENDING → CHECKING → READY/REJECTED；对象尚未到达、扫描服务暂时不可用回到可重试 PENDING 并显示原因，不能当作已通过。检查至少包括声明大小与实际大小、允许类型的文件特征、病毒扫描、SHA-256 摘要；扩展名不能代替实际类型检查。扫描失败关闭公开能力，检查通过的含义仅是本流程未发现所检查风险。

沿用现有检查的短事务和尝试 token 隔离：150 秒检查租约、140 秒服务等待上限，外部读取/扫描在数据库锁之外；结果回来后锁内重查身份、撤回、记录有效性与尝试 token。超时后台线程可能继续，旧结果不能覆盖新尝试或复活已撤回文件。业务时间使用可注入 Clock。

本人可“移除未公开文件”，腾出库存；正在公开的文件只允许明确“撤回公开文件”。取消草稿勾选不腾库存；成功更新不再引用的文件可再移除。移除/撤回使用逻辑标记，历史快照引用保留；本轮不物理删除历史对象、不实施存储保留清理，后续 R10 制定正式保留与配额。

撤回仅永久禁止该文件再次公开；本人仍可私有下载原来已 READY、未移除的文件。已移除记录只保留历史元数据，不提供普通本人内容读取；REJECTED 或未 READY 的字节也不给本人内容接口返回。关闭档案本身不会移除文件。

公开下载必须经过身份鉴权的 API 代理，不给可绕过关闭开关的 presigned GET 或对象 key。本人私有读取走独立权限入口。后端先鉴权、在锁外有界读取并比对 MIME/大小/摘要，返回前再鉴权与审计；以最终授权事务为读取的排序点，关闭、撤回或账号失效在该事务之前提交时，即使文件已经读入后端内存也不能输出。不承诺收回此前已授权、开始返回的字节。下载返回安全文件名、`Content-Disposition: attachment`、`X-Content-Type-Options: nosniff`、`Cache-Control: private, no-store`。文件内容不自动嵌入列表/详情，不在浏览器执行 PDF/HTML。

客户端上传失败保留原上传记录并显示检查/重试入口；相同 write-once PUT 收到 412 不能直接宣称已上传成功，由后端检查确认既有对象。页面刷新丢失 File 对象时先查服务端状态；如果仍缺字节，可显式移除旧记录后重新选择文件，不能静默另建请求。扫描未完成时允许保存草稿，但不能公开勾选该文件。

## 6. 查询、权限与接口边界

公开可见条件：当前校内身份 ACTIVE、档案主人 ACTIVE STUDENT、本人 VISIBLE、治理 NORMAL、有有效公开快照。本轮用现有已登录演示身份，页面明确当前未接学校 SSO。本人关闭后的管理读取与公众读取权限完全分开；其他人的未公开/无权/不存在档案使用相同中性 404。

列表默认每页 20、最多 50，offset 分页；排序为公开更新时间倒序、档案 ID 固定次序。支持最长 100 字关键词、最多 5 个标准标签（全部匹配）、单一合作状态；无筛选显示全部可见档案，包含“暂不接洽”。筛选保存在 URL，返回列表保留条件与页码。关键词按字面转义 SQL 通配符，搜索公开的姓名、院系、介绍、优势、标准标签名称、技能补充、合作方向/角色、经历；不搜索草稿、联系值、学号或文件内容。

公开 DTO 是字段白名单，只含本规格允许的基本资料、优势/意向/状态、可选经历/链接、文件名称/类型/大小与路由用公开资源 ID、授权渠道种类、公开版本/时间。列表使用摘要子集且不附联系值/完整经历/文件字节。禁止账户 user_id、学号、对象 key、上传 URL、扫描内部信息、治理备注进入公开 DTO；显式授权后的联系值响应是单独的受限例外。

全部 `/api/v1/ie/` 成功/错误响应继续使用现有 `InnovationPrivacyMiddleware` 的 private/no-store；人才数据不做共享缓存、静态公开生成或 CDN 缓存。关闭后的安全性依赖每次读取的当前数据库授权，不依赖搜索索引、缓存清理或客户端是否刷新。已经合法读到、复制、下载的内容无法远程收回，关闭说明准确表述“停止后续访问”。

建议的接口分组（最终契约名称在实施计划落实，不改变以下语义）：

| 分组 | 路径与职责 |
| --- | --- |
| 本人档案 | `GET /ie/me/talent-profile`；创建、保存、发布、关闭及撤回命令位于同一资源下，命令含 request_id/version |
| 本人文件 | `/ie/me/talent-profile/files` 下申请、完成检查、移除/撤回、本人受限内容读取 |
| 校内浏览 | `GET /ie/talents`、`GET /ie/talents/{id}`；详情以 public_version 标识授权上下文 |
| 授权联系/文件 | `POST /ie/talents/{id}/contacts`、`GET /ie/talents/{id}/files/{file_id}/content`；均带 expected_public_version |
| 标签 | `GET /ie/talent-tags`；本人提交建议 `/ie/me/talent-tag-suggestions`，独立 request_id/指纹去重 |

联系读取沿用 Redis 限流基础设施，人才独立桶每用户 30 次/分钟；Redis 不可用返回 503，不绕过。授权读取前写审计，审计失败不给联系值/文件；审计只记录操作者、资源、动作与版本，不记录联系明文/文件内容。关闭等权限命令和审计同事务提交。

服务层拥有事务；router 保持薄。修改/敏感读取先锁相关查看者与主人账户（UUID 固定顺序），再锁人才档案，再按固定顺序锁文件/授权行；锁后重新校验，治理/账号状态变化遵守相同序列。普通列表/详情单次查询包含可见条件；长外部 I/O 不占用这些锁。数据库约束覆盖一人一档、文件大小/类型/状态、公开引用归属和命令唯一性；跨行不变量在真实 PG 事务中验证。

## 7. 前端与恢复体验

本人读取 DTO 额外返回私有 `moderation_state`（NORMAL/TAKEN_DOWN），以解释运营限制导致的停止展示；公开 DTO 不返回该字段或治理备注。该说明沿用既有治理规则，不增加本阶段运营操作。

复用既有设计 token、Field/Button/Dialog、创新创业导航和认证边界，不为人才库另造一套视觉体系；字段/状态、API、页面组合分离，后续 UI 优化可以调整布局而不重写公开权限规则。

手机与桌面均检查 loading、空库、未建档、服务错误、权限失效、长内容、扫描中/拒绝、版本冲突。提示说明具体字段和补救动作；校验失败聚焦第一项错误；预览/文件选择/返回动作有明确焦点恢复；成功和异步状态有可读公告，非仅颜色表达。首次无经验建档路径不被文件、联系或合作意向选填项阻塞。

继承 R3 验收修复经验：同标签当前登录会话内存保留未保存表单，站内返回说明已恢复；显式丢弃、退出/换号清理。不写 localStorage/IndexedDB，不跨用户共享。每次请求绑定 auth epoch；迟到响应、保存回执、文件检查响应不得显示上一账号内容，也不得清除后来新输入。上传 File 仅在当前页面/会话内存保留；刷新后按第 5 节恢复。

公开联系/文件撤回是独立明确动作，确认说明影响；取消不改变权限。无文件可公开、全部联系人未授权仍然可开启，不借用招募“必须至少一个联系方式”的规则。

## 9. 规格自审与下一阶段

### R4.1 补充（2026-10-13，用户授权展示短方案后实施）

列表增加 `has_public_materials` 布尔事实字段，筛选为同名可选 boolean（未传=全部）；只有当前公开版本引用、归属本档案、READY 且未移除/撤回的文件计入。未公开上传、草稿选择、旧版附件、仅文字经历或作品链接均不计入。标志、筛选及详情可读文件使用同一谓词；筛选在数据库分页/total 之前应用，不逐条读取详情，不改变默认排序。撤回或状态不可读后下次读取同步变化，关闭/治理/失效账号仍遵守原可见条件。

标志为中性回形针及“含作品/证明材料”；相关界面说明“材料由本人提供，文件安全检查不代表内容真实性或能力已核实”。无材料不标红、不降权，不成为新生建档门槛。人才列表压缩筛选、技能标签换行、突出优势；详情、本人编辑与预览分组为个人与优势、合作意向、经历与作品、联系授权，保留原输入恢复和确认语义。材料真实性审核、全站重做、R5+ 均不纳入。
