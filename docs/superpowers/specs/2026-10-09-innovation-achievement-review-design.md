# 成果首次核实与校内展示设计

2026-10-09。用户在补充原 SRS 并核查差异后，明确要求“回顾一下学姐的两个文档之后就继续推进吧”，授权按本设计继续实施。基于已确认的独立需求 PR-06/08/11/12、OP-01、AC-01，以及技术实现文档 §5、§7.2、§9.1。复用已完成的负责人资格、运营授权和私有成果草稿；不重新讨论三库范围或负责人四项信息。

## 1. 交付与验收

本轮形成真实闭环：负责人保存成果与证明材料→提交核实→被管理员指定的运营领取审核→通过或说明原因退回→通过后校内登录账号可浏览。学生能查看状态、撤回待审、修改退回成果后重交；已通过的同一份成果后续更新免复审。新增另一份成果仍须首次核实。

学校统一认证仍沿用既有待对接项。当前本地 demo 使用已获用户许可的预置账号，不把本地登录说成学校认证完成；正式校内开放前必须完成可信身份接入。核实不自动发积分、不发布招募、不开放人才或导师档案。

用户只需用负责人、运营、普通浏览者三个演示账号验收：待审不可浏览；通过可浏览；退回原因可见；更新不产生第二个审核单；普通浏览者打不开证明材料。

## 2. 既有规则与本轮实现选择

既有规则不变：资格与成果核实分离；运营不能审核本人参与项目；证明材料只给负责人和该项目授权审核人员；待审版本不可被暗中替换；首次核实与内容下架分别记录；已公开更新免复审。

本轮实现选择：

- 运营看到不含四项身份信息和证明内容的待办目录，显式领取后才获得该审核单的材料读取权。领取、访问、决定均审计；撤权或账号停用后下一次请求立即拒绝。
- 审核快照包含已保存的项目概况、成果四项内容、负责人四项资料和已通过文件安全检查的证明引用及摘要。审核单只针对这个不可变版本。
- 首次提交要求负责人资格 APPROVED、项目五项概况完整、成果名称和说明完整，以及至少一份证明。作品链接和获奖说明可选，不强制获奖或成熟项目经历。
- 本地 demo 初始材料策略建议 PDF、PNG、JPEG，单文件最多 10 MiB、每次提交最多 5 份；这些是可调整的实施参数，不是学校制度。拒绝压缩包、可执行文件和任意远程抓取。
- 已公开成果更新继续保留本人草稿。负责人显式“发布更新”才生成新公开版本；“保存草稿”不改公开内容。保留首次核实日期、最近更新时间，并标明后续更新未逐项复审。
- 当前仓库只有项目负责人关系，没有共同管理员和已确认成员关系。此轮真实执行负责人回避，并支持运营主动声明其他利益冲突；不从团队简介字符串推测成员身份。共同管理/成员功能接入时必须扩展关系回避，完整平台验收前不可跳过此项。

## 3. 状态、版本与并发

每份成果独立保存 first_review_state：DRAFT、SUBMITTED、RETURNED、APPROVED；另保存 moderation_state：NORMAL、TAKEN_DOWN。审核单有 SUBMITTED、APPROVED、RETURNED、WITHDRAWN 状态，不复用任务 Claim/Submission。

- 首次提交生成不可变 revision 和 review_case；重复提交使用 request_id 与首次载荷指纹返回同一结果，同键不同内容 409。
- SUBMITTED 期间禁止修改成果正文；显式撤回关闭旧审核单，再修改、保存、提交新版本。项目草稿的后续编辑不改变审核快照，也不随旧审核通过自动公开。
- 决定必须匹配 review_case 版本、revision_id、领取人和当前状态。撤回与批准竞争只能有一方成功，另一方 409；不得重复批准、产生重复审核通知或覆盖新版本。
- 领取人被撤权、停用或不再是运营学生时，其他有效运营可从待办领取失效的分配。先按顺序锁定当前、原领取人和负责人账号，并在锁后重新检查原领取人的实际资格；有效领取不能被抢占，接手递增审核单版本并审计。声明项目级回避释放本人在该项目全部未关闭申请，逐条递增版本并审计；其他项目与已完成决定保留。
- APPROVED 的公开更新生成不可变 revision 并原子切换 public_revision_id，不创建新审核单，不重写 first_approved_at。若被下架，更新不能恢复公开。
- 数据库约束保护状态组合、每份成果的版本号、提交请求唯一性和公开版本归属。业务时间使用现有 Clock；锁顺序固定为按 UUID 排序的相关用户→运营授权/负责人资格→项目→成果→审核单/材料。远程存储或扫描调用不在持有这些业务锁时执行。

## 4. 证明材料与文件服务

沿用已有 ObjectStorage 端口、S3/MinIO 适配和单次写入签名规则，增加双创专用对象前缀与领域方法；不借用科研任务 claim_id，不放宽 CSV/XLSX/SQLite 的现有校验。

上传意向只由负责人创建，绑定本人项目和成果，随机对象名由服务端生成，限制类型、大小、数量和有效期。完成上传后核对真实对象、字节数、类型与文件摘要，执行独立安全检查。状态为 PENDING、CHECKING、READY、REJECTED；READY 前不可作为提交材料，也不可由审核人下载。

安全检查先核对文件签名与声明的 PDF/PNG/JPEG 类型，再通过本地隔离 ClamAV 服务执行病毒扫描；使用 INSTREAM 发送受限字节流，不把浏览器文件名当作服务端路径。单次扫描超时 30 秒，扫描器必须加载官方病毒库、支持所需命令并满足至少 10 MiB 的扫描限额；只有收到明确的 OK 且完整处理了限额内文件，才允许 READY。发现威胁、类型错误、扫描限额跳过、协议异常或服务不可用均不放行，记录脱敏结果并允许对临时失败重试。ClamAV TCP 仅限内部或回环网络，不公开端口；部署为独立服务，不给 Web 进程执行文件权限。

新增真实扫描服务及其健康检查是本轮实施工作，不假设本机现已安装。类型校验和病毒检查分别测试，READY 不等于人工核实或绝对安全；损坏文件、威胁测试样本和检查器不可用必须有明确拒绝证据。扫描命令与连接边界依据 [ClamAV 扫描说明](https://docs.clamav.net/manual/Usage/Scanning.html) 及 [ClamD 协议](https://docs.clamav.net/manual/Usage/ClamdProtocol.html)。

证明下载通过每次鉴权的 API 代理，不返回对象 key、桶名或可绕过撤权的下载签名 URL；强制 attachment 下载、nosniff、private/no-store。读取先提交不含文件内容的 durable 审计，失败时不返回文件。服务端读取和扫描均有大小、时间和资源边界，不解析执行上传内容。

提交后的材料引用不可替换或删除以改写审核历史。未提交且无引用材料允许负责人移除；留存期限遵循既有待配置项，不擅自永久保存全部敏感资料，也不添加自动删除历史证据的定时任务。

## 5. 领域与接口

在 innovation 域增加 achievement_workflow、achievement_revision、achievement_review_case、achievement_evidence 四类对象，使用明确外键连接已有 AchievementDraft/ProjectDraft。追加新 Alembic 迁移，不改 0025–0029 历史。源码按 review_models、review_schemas、review_service、review_router 和 evidence_service 分工，路由不直接实施多表转换。

本人管理端在现有 `/ie/me/project-drafts/{project_id}/achievements/{achievement_id}` 下追加 workflow、submit、withdraw、publish-update、evidence 资源；提交只接受已保存版本、材料 ID 与请求 ID，不接受 owner/reviewer/approval/points 字段。

运营端 `/ie/ops/achievement-reviews` 提供待办目录、claim、detail、decision。决定为 APPROVED 或 RETURNED；退回须说明原因。审核人只看当前分配给自己的已提交快照，不能借页面入口读取未提交草稿或其他项目全部证明。ADMIN 负责指定运营和无冲突分配，不因全局角色直接变成成果审核人。

浏览端 `/ie/achievements` 提供分页列表及公开版本详情，均校验有效登录身份与可见状态。响应只从 public_revision 读取公开白名单；不直接序列化草稿、review_case、四项资料或 evidence。不向匿名用户返回成果，直链与列表执行同一规则。

## 6. 页面与验收工件

扩展已有成果编辑器，分别显示保存状态、核实状态和公开状态；明确区分保存、提交、撤回与发布更新。附加证明列表和类型/大小限制，未知提交结果保留输入并先重读。运营工作区使用学生布局和独立授权，不放进仅 ADMIN 可用的后台。

新增校内成果列表和详情；无成果时使用真实空状态。复用项目组件、设计 tokens、命名区域、键盘确认和账号切换请求隔离；手机优先，避免在卡片和错误日志泄漏学号或材料路径。

按仓库门禁执行：先写规约对账与失败用例，再实现；真实 PG 验证身份/归属/回避、撤权、审计原子性、两个连接的撤回/批准竞争、每份成果独立首次核实；真实 MinIO 验证文件意向、类型/大小拒绝、内容检查与受控读取。同步 OpenAPI、生成类型、选择器、skip 契约、固定字体 Linux PNG；跑相关前后端模块、浏览器手机/键盘、axe、覆盖率及扩大门禁，分开记录未执行和既有全站缺口。

用户 2026-10-09 已验收负责人申请界面；本文件不会把该反馈扩大为成果审核、文件安全或全平台验收通过。设计确认后再拆实施任务，先逐项本会话执行，不自动启用多代理；需要独立评审时按届时授权处理。
