# CampusQuest V1.1 — Experience & Administration Design

> Status: **DRAFT — awaiting owner review**
> Date: 2026-10-15 · Supersedes: none (amends V1 spec §5.6/§5.8; see §2)
> Theme: 用得顺（登录/效率）+ 管得住（管理员权力包/运营便利）

## 0. 背景与目标

V1 已上线生产（2026-10-12 production flip）。运营暴露的第一手痛点：员工认证过重
（owner 亲历 TOTP 绑定卡壳、每次登录三要素）、管理动作依赖 ssh（发邀请/看家底/清库）、
管理员对教师/学生缺乏细粒度管理工具。V1.1 一次性补齐三类能力，不做激励扩展
（克制游戏化红线不动）。

成功标准：教师从邀请到首次登录 ≤3 步且零 TOTP；管理员不 ssh 完成全部日常运营；
每个新管理动作有审计行。

## 1. 范围

**In**：认证简化（Wave 1）、管理员权力包、运营便利、教师效率、账号安全补强、
随车安全裁定。**Out（V1.2+ 或不做）**：Passkey、微信登录、深色模式、荣誉体系扩展、
任务广场搜索（等任务量）、审核批量操作、学期个人报告。

## 2. 认证体系修订（amends V1 spec §5.6/§5.8）

### 2.1 教师登录：邮箱验证码两步流

输邮箱 → 收 6 位邮件码（5 分钟有效）→ 输码即登录。无密码、无 TOTP。

- 实现：镜像现有 SMS OTP 挑战架构（存储/限速/模板），通道走已接通的 SMTP
  适配器（PR #79）；新 `LoginEmailChallenge`，不与学生手机挑战混表。
- 限速：同邮箱 60s 重发冷却；邮箱+IP 双桶（复用 #76 限速基建）。
- 权衡（owner 2026-10-15 批准）：邮箱即身份。教师可**自愿**加开 TOTP
  （账号设置里），默认关。spec §5.6"员工强制 2FA"修订为：
  **TEACHER = 邮箱码单因子（可选 TOTP 增强）；ADMIN = 邮箱码 + 强制 TOTP**。
- **已知侧信道（Wave 1 终审 F4，reviewer 2026-10-15 裁定记档）**：验证码
  邮件在请求内同步投递，真实 SMTP 下员工邮箱与未知邮箱的响应耗时存在
  统计可分差，可作员工邮箱枚举探针。V1.1 接受该残余风险（员工邮箱本
  高度可猜 + 60s 冷却与限流约束探测速率）；**缓解=发送队列化**（202 先
  返回、投递转后台），属产品语义变更，列为 follow-up，不随 Wave 1。

### 2.2 管理员登录与"记住此设备"

- 流程：邮箱 → 邮件码 → TOTP（首次/新设备）。
- 记住此设备：登录成功时可勾选；签发 30 天设备凭据（独立 cookie，与 refresh
  token 分离，HttpOnly+SameSite）。有效期内 ADMIN 登录 = 邮箱 → 邮件码 → 进。
- 用户可查看/清除自己的记住设备（账号设置）；管理员会话踢线（§3.3）同时失效
  该用户全部设备凭据。

### 2.3 邀请激活减负

- TEACHER 接受邀请：设**可选**密码 → 直接 ACTIVE（无 TOTP 绑定步骤；不设密码
  则纯邮箱码流）。
- ADMIN 接受邀请：维持现行 TOTP 绑定 + 恢复码发放。

### 2.4 兼容与回退

- 现有"邮箱+密码+TOTP"登录通道保留（密码已设的员工可继续用）；恢复码通道
  保留。旧账号零迁移成本。
- 登录页员工入口优化：学生/员工登录一键切换更显眼。

## 3. 管理员权力包（管理教师与学生）

全部新端点挂 `/api/v1/admin/*`，`require_admin_actor` + 管理网段依赖不变，
**每个动作写审计行**（复用 AuditLogWriter flush-only 纪律，PR #80 模式）。

### 3.1 用户详情全景 `GET /admin/users/{id}`

聚合：profile/状态/角色/钱包余额/最近 10 条提交/活跃会话数/记住设备数。
前端：用户表行点击进详情页（users 列表页已有，加详情视图）。

### 3.2 管理员代重置密码 `POST /admin/users/{id}/password-reset`

自助通道失效（邮箱/手机均不可达）时的兜底：签发**一次性重置链接**（复用邀请
token 工艺：urlsafe(32)、哈希落库、48h 有效），管理员转交用户，用户打开设新
密码。审计 `ADMIN_PASSWORD_RESET_ISSUED` / `ADMIN_PASSWORD_RESET_CONSUMED`。
不可用于自身（自己走自助通道）。

### 3.3 会话管理 `GET /admin/users/{id}/sessions` + `DELETE`（踢线）

查看目标用户活跃会话；DELETE 撤销其全部 refresh token + 记住设备凭据（被盗
应急）。审计 `ADMIN_SESSIONS_REVOKED`。被踢用户下次请求即 401。

### 3.4 角色升降 `PATCH /admin/users/{id}/role`

TEACHER↔ADMIN（V1 spec §5.8 预留的 promote/demote）。约束：不可改自身角色；
不可降级最后一个 ACTIVE ADMIN（服务层校验+DB 约束双保险）。审计
`ADMIN_ROLE_CHANGED`（before/after 快照）。

### 3.5 批量账号操作 `POST /admin/users/batch`

`{action: "suspend"|"reactivate", user_ids: []}`（上限 100/批）。复用现有
`_transition_account_status` 语义（不引入新状态机分支）。逐行结果返回
（成功/跳过+原因）。审计每行一条。

## 4. 运营便利

### 4.1 管理台概览 `GET /admin/overview` + 仪表盘页

一次性聚合：总用户数（按角色/状态分）、任务状态分布、待审提交数、待审兑换数、
今日新增/活跃（会话表口径）、白名单规模。前端 `/admin` 首页改为仪表盘
（原 users 页保留在导航）。

### 4.2 邀请生命周期

- `GET /admin/staff/invitations`：列表（邮箱掩码显示/角色/状态=待接受·已接受·
  已过期·已撤销/签发人/时间）。
- `DELETE /admin/staff/invitations/{id}`：撤销未接受的（token 立即失效）。
- `POST /admin/staff/invitations/{id}/resend`：对未接受/已撤销的重签新 token
  （旧 token 失效，响应一次性返回新链接）。
- **占用预检**（补 create 侧缺口，前端会话 2026-10-14 实证）：create 时邮箱
  已有账号 → 409（前端映射已备好）。
- G11 纪律：邮箱明文只存 invitation 行，列表响应可含（管理面，非学生面）。

### 4.3 白名单学期批量

- 批量清退（batch disable，勾选/按学期标签）；导入保留现有 preview/confirm 流。
- 学期轮换视图：`/admin/whitelist` 加"按入学届别筛选"（whitelist 行补届别
  字段——需要小迁移，默认空=历史导入）。

## 5. 教师效率

- **任务复制重发** `POST /tasks/{id}/duplicate`：复制为 DRAFT（清空发布时间/
  领取/提交数据；保留 schema/奖励/协作者），发起者成为 owner。
- **提交批量导出** `GET /tasks/{id}/submissions/export`：CSV（每提交一行：学号/
  状态/校验结果/分数/时间），仅 owner+协作教师；流式生成限 1 万行。
- **通知渠道偏好** `GET/PATCH /me/notification-preferences`：按类别（任务提醒/
  审核结果/兑换/系统）选渠道子集（站内必开；短信/邮件可选关）。投递层尊重偏好。

## 6. 账号安全补强

- **账号锁定**：同一账号连续 5 次登录失败 → 15 分钟冷却（学生/员工通用；计数
  与 IP 限速独立；成功登录清零）。防在线爆破账号维度短板（现仅 IP 维度）。
- **首登引导改昵称**：昵称=自动生成形态（数字串/学号）的账号，登录后一次性
  气泡引导改名（可跳过，不再骚扰）。

## 7. 随车裁定与运维项（非产品功能，随 V1.1 一并落）

- 批 4 挂账三项裁定建议：②TOTP 重放窗（30s±1 窗收紧为拒绝旧窗码）、③CSV
  公式注入（导出时公式首字符转义——与 §5 导出功能同 PR 做）、⑥管理 CIDR
  （默认策略收紧为显式配置才放开，system_settings 落策略）。①pending-TOTP
  会话边界维持现状（30 分钟 pending TTL 已够短）。
- 生产 DB 每日备份（pg_dump 到本机独立目录+保留 7 份；owner 侧可选异地）。
- 服务器 `build-frontend.sh` 固化三变量构建配方。

## 8. 测试与验收

- 认证流全部分支 e2e（教师码流/ADMIN 记住设备/锁定冷却/409 占用/重置链接）；
- 管理端点权限矩阵测试（TEACHER/STUDENT 对 admin 端点全 403；ADMIN 正常）；
- 审计行断言：每个新管理动作一组（动作/actor/before-after 快照）；
- 并发：最后一个 ADMIN 保护（两 ADMIN 并发自降）；重置链接一次性（并发消费）；
- 像素基线：新页面（仪表盘/用户详情/邀请列表）按钉字体纪律；截图验收登录页
  与员工入口改造；
- G19 工件清单全 PR 走查；OpenAPI 快照+TS 类型随 API PR 再生（docstring 教训）。
