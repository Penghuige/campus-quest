# 双创 R2：已公开成果更新复审

2026-10-10。依据用户已确认决定与 `docs/handovers/2026-10-10-innovation-roadmap.md` R2，覆盖旧设计中的免复审更新规则。R1 已交付，用户明确要求继续推进；不重复确认既定方向。

## 内容和权限边界

- 每次已公开成果更新均提交更新复审，使用当前已保存版本生成不可变快照，不接受客户端正文副本。
- 快照包含成果名称、说明、作品链接、奖项，以及项目名称、概况、方向、阶段、团队状态。仅保存项目草稿不会改变任何已公开成果；下一次提交该成果时固定最新项目信息。
- 姓名、学号、专业、年级和证明属于私有审核资料。个人资料修改不会自动触发其他成果的复审或改变公开内容。
- 负责人资格、项目归属、账号状态、运营授权、领取、回避、私有证明访问审计保持后端权威。
- 招募、学校统一认证及 R3+ 不在本轮范围；预置账号和模拟资料标识保留。

## 生命周期

- `first_review_state=APPROVED` 表示已完成首次核实，不随更新待审、退回、撤回回退。当前审核事项由最新 `review_case.status` 与 `operation=SUBMIT|UPDATE` 表达。
- 保存新版、提交更新、退回更新、撤回更新均保留旧公开指针和公开时间；新版通过时，在同一事务中替换公开指针并写通知及审计。
- 首次通过时间永久保留；最近公开更新时间仅在通过时修改。公开响应增加本版审核通过时间 `latest_reviewed_at`，来源于当前公开版本的通过记录。
- 既有未复审历史 UPDATE 记录不伪装成已复审：本版审核时间为空，页面标注历史更新未逐项复审。不批量重审或重置开发数据。
- 每个成果最多一个待审事项；待审时成果和证明不能修改，先撤回。项目草稿可独立修改，已提交快照保持不变。
- 退回后保留原因，可修改后重新提交；撤回后可重新提交。每次新提交产生新版本、新事项；旧请求重放不得重复生成事项，旧撤回/决定不得影响新版。
- 使用项目、成果、工作流、事项锁及版本 CAS（比对请求与当前版本）串行化批准/撤回竞争；两种动作只能一个成功。下架状态始终保留，更新通过不能绕过下架。

## API 和界面

- 新操作 `POST .../submit-update`，移除 `publish-update` 即时发布入口，旧地址不可改变公开数据。
- 审核事项响应必须包含 `operation`，负责人、运营队列和详情区分首次核实与更新复审。
- 负责人按钮为“提交更新复审”，确认说明“审核期间保留旧通过版本及原公开状态，通过后才替换；已下架成果保持下架”。待审提示、退回原因、撤回状态与公开链接相互一致。
- 校内成果页面展示首次核实、本版核实时间；已复审新版不显示“未逐项复审”。私有资料和内部版本编号不进入公开 DOM。
- 原有请求重试、会话隔离、键盘确认、移动端布局保持有效。

## 验收

负责人发布 V1，通过后保存并提交 V2；观察者始终看到 V1。运营退回或负责人撤回 V2 后仍看到 V1。重新提交并通过 V3 后才展示 V3，首次核实时间不变。重复提交和并发决定不产生错误公开版本；下架后通过更新仍不可浏览。
